第10、11讲作业

第10讲

4.51

iaddq V, rB 将立即数 V 与寄存器 rB 中的值相加，将结果写回 rB，并根据加法结果设置条件码。各阶段执行的计算如下：

阶段 计算
取指 icode:ifun ← M₁[PC]；rA:rB ← M₁[PC + 1]；valC ← M₈[PC + 2]；valP ← PC + 10
译码 valB ← R[rB]
执行 valE ← valB + valC；设置条件码 CC
访存 无
写回 R[rB] ← valE
更新 PC PC ← valP

其中，M₁ 表示读取 1 字节，M₈ 表示读取 8 字节，R[rB] 表示寄存器 rB 中的值。

取指阶段与 irmovq 类似：指令包含 1 字节的指令代码、1 字节的寄存器指示符和 8 字节的立即数，共 10 字节。icode = 0xC，ifun = 0，rA = 0xF 表示不使用该寄存器字段，rB 指定目标寄存器；valC 取得立即数 V。

译码阶段只读取 rB 的原值，不需要读取 rA。执行阶段选择 valC 和 valB 作为 ALU 的两个输入，执行加法，并像 addq 一样更新 ZF、SF、OF。结果为零时 ZF = 1，结果最高位为 1 时 SF = 1，发生有符号加法溢出时 OF = 1。

该指令不读写数据内存，最后将加法结果 valE 写回 rB，并将 PC 更新为下一条指令的地址 valP。

第11讲

4.57

A. 加入加载转发后，需要暂停的加载/使用冒险条件为：

E_icode in { IMRMOVQ, IPOPQ } &&
(
    E_dstM == d_srcB ||
    (E_dstM == d_srcA && !(D_icode in { IRMMOVQ, IPUSHQ }))
)

E_icode 是当前执行阶段指令的代码，E_dstM 是该指令从内存加载数据后要写入的寄存器；D_icode 是当前译码阶段指令的代码，d_srcA、d_srcB 是它的两个源寄存器。

当 E_icode 为 IMRMOVQ 或 IPOPQ 时，前一条指令需要从内存加载数据。如果 E_dstM == d_srcB，后一条指令在执行阶段就需要这个值，例如用它计算访存地址，因此仍须暂停。

如果 E_dstM == d_srcA，只有后一条指令是 rmmovq 或 pushq 时，可以通过加载转发避免暂停。这两种指令将 valA 作为待写入内存的数据，到访存阶段才需要它。当加载指令处于访存阶段、存储指令处于执行阶段时，可以将 m_valM 直接前递到流水线寄存器 M 的 valA 字段，供存储指令在下一个周期使用。其他指令对 d_srcA 的这种依赖仍须暂停。

例如：

mrmovq 0(%rcx), %rdx
pushq %rdx

pushq 只把 %rdx 用作待存储的数据，可以通过加载转发消除这次加载/使用暂停。

popq %rdx
rmmovq %rax, 0(%rdx)

这里 %rdx 是 rmmovq 的地址基址，即 d_srcB，执行阶段就要使用，因此仍须暂停。

如果同一个寄存器同时作为存储数据和地址基址，例如 rmmovq %rdx, 0(%rdx)，也必须暂停；公式中的 E_dstM == d_srcB 保证了这种情况不会被漏掉。
