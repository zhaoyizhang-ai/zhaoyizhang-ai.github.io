第14讲

5.13

A. 将一次迭代中的指令分解为操作后，数据依赖关系如下。其中，load u 和 load v 包括地址计算和从内存读取数据，mul、add 分别表示乘法和加法。

                       i
                       |
              +--------+--------+
              |                 |
         load u[i]         load v[i]
              |                 |
              +--------+--------+
                       |
                      mul
                       |
sum（本次输入）-------> add -------> sum（下次输入）

i（本次输入）---------> +1 --------> i（下次输入）
                       |
                 与 limit 比较
                       |
                     条件跳转

vmovsd 对应读取 udata[i]；带内存操作数的 vmulsd 可分解为读取 vdata[i] 和乘法；vaddsd 将乘积加到 sum 中。addq 更新下标，cmpq 和 jne 控制循环。

跨迭代的累加依赖链为：

sum₀ ---> add₀ ---> sum₁ ---> add₁ ---> sum₂ ---> add₂ ---> …
           ^                   ^                   ^
           |                   |                   |
       u[0]*v[0]           u[1]*v[1]           u[2]*v[2]

每次加法必须等待前一次加法产生的 sum，因此连续的加法构成限制循环稳态执行速度的关键路径。各次迭代的乘法不依赖前一次的 sum，可以提前执行并相互重叠。

B. 根据图 5-12，double 加法的延迟为 3 个时钟周期。每处理一个元素，都必须沿累加依赖链执行一次加法，因此：

CPEmin⁡=3.00.\mathrm{CPE}_{\min}=3.00.CPEmin​=3.00.

C. 整数加法的延迟为 1 个时钟周期，所以这条关键路径给出的下界为：

CPEmin⁡=1.00.\mathrm{CPE}_{\min}=1.00.CPEmin​=1.00.

整数乘法虽然有 3 个周期的延迟，但不同迭代的乘法相互独立，不构成跨迭代的乘法依赖链。

D. 两种浮点版本指 float 和 double。它们的乘法延迟均为 5 个周期，但浮点乘法单元是流水线化的，而且不同迭代的乘法可以并行执行。处理器不必等到前一次乘法完成，才开始下一次乘法。

因此，乘法的 5 周期延迟不会变成每个元素都必须串行付出的代价。真正限制稳态执行速度的是 sum 上延迟为 3 个周期的连续加法，所以两种浮点版本的 CPE 都可以达到 3.00。

5.14

6×1 循环展开表示每次迭代处理 6 个元素，但仍然只使用一个累积变量。代码如下，vec_ptr、data_t 及向量接口沿用教材定义。

void inner6x1(vec_ptr u, vec_ptr v, data_t *dest)
{
    long i;
    long length = vec_length(u);
    long limit = length - 5;
    data_t *udata = get_vec_start(u);
    data_t *vdata = get_vec_start(v);
    data_t sum = (data_t)0;

    for (i = 0; i < limit; i += 6) {
        sum = sum + udata[i] * vdata[i];
        sum = sum + udata[i + 1] * vdata[i + 1];
        sum = sum + udata[i + 2] * vdata[i + 2];
        sum = sum + udata[i + 3] * vdata[i + 3];
        sum = sum + udata[i + 4] * vdata[i + 4];
        sum = sum + udata[i + 5] * vdata[i + 5];
    }

    for (; i < length; i++) {
        sum = sum + udata[i] * vdata[i];
    }
    *dest = sum;
}

主循环每次处理 6 项，剩余不足 6 项的部分由末尾循环处理。

A. 计算内积的每个元素都需要读取 udata[i] 和 vdata[i]，即执行两次加载。教材参考机每个周期最多执行两次加载，因此仅加载操作就给出了：

CPE≥2 次加载/元素2 次加载/周期=1.00.\mathrm{CPE}\geq\frac{2\text{ 次加载/元素}}{2\text{ 次加载/周期}}=1.00.CPE≥2 次加载/周期2 次加载/元素​=1.00.

所以任何按题设执行这些标量操作的版本都不能达到小于 1.00 的 CPE。此外，整数乘法每周期最多执行一次，浮点加法每周期最多执行一次，也分别对相应数据类型给出了 1.00 的吞吐量下界。

B. 6×1 展开只减少了下标更新、比较和跳转的次数，没有打断 sum 的依赖链。每组中 6 次浮点加法仍然依次依赖，至少需要 6×3 = 18 个周期，所以：

CPEmin⁡=186=3.00.\mathrm{CPE}_{\min}=\frac{18}{6}=3.00.CPEmin​=618​=3.00.

因此浮点版本仍然受加法延迟限制，题目给出的 CPE 为 3.01，性能几乎没有提高。

5.15

6×6 循环展开使用 6 个独立的累积变量，每个累积变量处理一组下标，最后再将它们相加。

void inner6x6(vec_ptr u, vec_ptr v, data_t *dest)
{
    long i;
    long length = vec_length(u);
    long limit = length - 5;
    data_t *udata = get_vec_start(u);
    data_t *vdata = get_vec_start(v);
    data_t sum0 = (data_t)0;
    data_t sum1 = (data_t)0;
    data_t sum2 = (data_t)0;
    data_t sum3 = (data_t)0;
    data_t sum4 = (data_t)0;
    data_t sum5 = (data_t)0;

    for (i = 0; i < limit; i += 6) {
        sum0 = sum0 + udata[i] * vdata[i];
        sum1 = sum1 + udata[i + 1] * vdata[i + 1];
        sum2 = sum2 + udata[i + 2] * vdata[i + 2];
        sum3 = sum3 + udata[i + 3] * vdata[i + 3];
        sum4 = sum4 + udata[i + 4] * vdata[i + 4];
        sum5 = sum5 + udata[i + 5] * vdata[i + 5];
    }

    for (; i < length; i++) {
        sum0 = sum0 + udata[i] * vdata[i];
    }
    *dest = (sum0 + sum1) + (sum2 + sum3) + (sum4 + sum5);
}

6 条累加依赖链相互独立，处理器可以交错执行它们。对于浮点数，每条链每处理 6 个元素才需要更新一次，其延迟界限降为 3 / 6 = 0.50 CPE，因而不再是主要瓶颈。

这时限制性能的是吞吐量：每个元素需要两次加载，而参考机每周期最多执行两次加载，所以加载吞吐量将 CPE 限制在不低于 1.00。整数版本还受每周期一次整数乘法的限制，浮点版本还受每周期一次浮点加法的限制。因此该版本可以接近 1.00，却不能低于这一界限。

题目给出的整数 1.06、浮点 1.01 是实测值；循环控制、余数处理和最终合并等开销使实际结果略高于理想下界。

5.16

6×1a 循环展开仍然只使用一个跨迭代的累积变量，但先计算一组 6 个乘积的和，再将组内结果加入 sum，从而改变加法的结合方式。

void inner6x1a(vec_ptr u, vec_ptr v, data_t *dest)
{
    long i;
    long length = vec_length(u);
    long limit = length - 5;
    data_t *udata = get_vec_start(u);
    data_t *vdata = get_vec_start(v);
    data_t sum = (data_t)0;

    for (i = 0; i < limit; i += 6) {
        data_t p0 = udata[i] * vdata[i];
        data_t p1 = udata[i + 1] * vdata[i + 1];
        data_t p2 = udata[i + 2] * vdata[i + 2];
        data_t p3 = udata[i + 3] * vdata[i + 3];
        data_t p4 = udata[i + 4] * vdata[i + 4];
        data_t p5 = udata[i + 5] * vdata[i + 5];

        sum = sum + ((p0 + p1) + (p2 + p3) + (p4 + p5));
    }

    for (; i < length; i++) {
        sum = sum + udata[i] * vdata[i];
    }
    *dest = sum;
}

每组中的乘法和组内求和都不依赖旧的 sum，可以提前执行；旧 sum 到新 sum 的依赖路径上只剩一次加法。对于浮点数，处理 6 个元素的跨迭代累加延迟为 3 个周期，对应的延迟下界为 3 / 6 = 0.50 CPE。最终性能仍受加载及算术操作的吞吐量限制，因此题目中浮点版本的 CPE 可以接近 1.00。

与 6×1 不同，6×6 和 6×1a 都改变了加法顺序。浮点加法不满足结合律，因此它们的结果可能与原程序存在舍入差异；整数版本的等价性在运算不发生有符号溢出的前提下成立。

7.6

各符号的情况如下。表中的“节”指符号在定义它的模块中所在的节。

符号 swap.o 的 .symtab 中有条目？ 符号类型 定义符号的模块 节
buf 是 外部 m.o .data
bufp0 是 全局 swap.o .data
bufp1 是 局部 swap.o .bss
swap 是 全局 swap.o .text
temp 否 - - -
incr 是 局部 swap.o .text
count 是 局部 swap.o .bss

buf 在 swap.c 中用 extern 声明，在 m.c 中定义并初始化为 {1, 2}，所以它在 swap.o 中是未定义的外部符号，实际定义位于 m.o 的 .data 节。

bufp0 是已初始化的全局指针，放在 .data 中。bufp1 带有 static，只在当前模块内可见，且未显式初始化，所以是 .bss 中的局部符号。

swap 是全局函数，incr 是 static 函数，二者代码均位于 .text，但前者是全局符号，后者是局部符号。

temp 是普通自动局部变量，不在链接器符号表 .symtab 中。count 虽然定义在函数内部，但它是 static 局部变量，具有静态存储期，会生成局部符号；其初值为 0，因此放在 .bss 中。

7.8

A. 两个 main 分别解析到各自模块中的定义：

(a) REF(main.1) → DEF(main.1)
(b) REF(main.2) → DEF(main.2)

模块 1 的 main 是全局函数，模块 2 的 main 是 static 局部变量。模块 2 的局部符号不参与跨模块的全局符号冲突，所以两者可以同时存在。

B. 两项都填“未知”：

(a) REF(x.1) → 未知
(b) REF(x.2) → 未知

按教材的强弱符号规则，两个未初始化的全局变量都是弱符号。链接器可以从多个弱定义中任意选择一个，因此无法仅由题目确定选择模块 1 还是模块 2；但选定之后，两处引用都解析到同一个定义。

这里沿用题目规定的弱符号/COMMON 合并模型。

C. 两项都填“错误”：

(a) REF(x.1) → 错误
(b) REF(x.2) → 错误

int x = 1 和 double x = 1.0 都是已初始化的全局变量，属于同名强符号。链接器不允许多个同名强符号定义，因此发生链接错误，不能完成符号解析。

7.12

R_X86_64_PC32 重定位项写入的值为：

value=S+A−P,\mathrm{value}=S+A-P,value=S+A−P,

其中，S 是 swap 的最终地址，A = -4 是附加值，P 是重定位字段本身的地址。本题中：

P=ADDR(.text)+0xA.P=\mathrm{ADDR}(\text{.text})+\text{0xA}.P=ADDR(.text)+0xA.

callq 指令位于节内偏移 0x9，长度为 5 字节；它的 4 字节位移字段从偏移 0xA 开始，下一条指令位于偏移 0xE。附加值 -4 将相对于字段起点的计算转换为相对于下一条指令地址的位移。

A. .text 的地址为 0x4004E0，因此：

P=0x4004E0+0xA=0x4004EA.P=\text{0x4004E0}+\text{0xA}=\text{0x4004EA}.P=0x4004E0+0xA=0x4004EA.

代入 swap 的地址 0x4004F8，得到：

value=0x4004F8−4−0x4004EA=0x0000000A.\mathrm{value}=\text{0x4004F8}-4-\text{0x4004EA} =\text{0x0000000A}.value=0x4004F8−4−0x4004EA=0x0000000A.

所以重定位引用的值为 0x0000000A，按小端序写入的 4 个字节为 0A 00 00 00，完整指令字节为：

e8 0a 00 00 00

下一条指令地址为 0x4004EE，加上位移 0xA，恰好得到目标地址 0x4004F8。

B. .text 的地址为 0x4004D0，因此：

P=0x4004D0+0xA=0x4004DA.P=\text{0x4004D0}+\text{0xA}=\text{0x4004DA}.P=0x4004D0+0xA=0x4004DA.

代入 swap 的地址 0x400500，得到：

value=0x400500−4−0x4004DA=0x00000022.\mathrm{value}=\text{0x400500}-4-\text{0x4004DA} =\text{0x00000022}.value=0x400500−4−0x4004DA=0x00000022.

所以重定位引用的值为 0x00000022，按小端序写入的 4 个字节为 22 00 00 00，完整指令字节为：

e8 22 00 00 00

下一条指令地址为 0x4004DE，加上位移 0x22，恰好得到目标地址 0x400500。
